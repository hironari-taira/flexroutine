# 配布・公開方針の決定ログ

更新日: 2026-07-12

## 結論

現時点では、FlexRoutineのGoogle Play一般公開を急がない。



これは「今後Google Playへ公開しない」という永久決定ではなく、**一般公開を保留する決定**である。

## 背景

- FlexRoutineは、バイブコーディングクラブでの練習とポートフォリオ作成を主目的として開発している。
- 現時点では収益化を予定しておらず、無料アプリとして公開しても直接的な収益は見込んでいない。


- 公開後は、Google Playポリシー、target SDK、依存ライブラリ、クラッシュ、問い合わせなどへの継続対応が発生する。
- ポートフォリオの目的は、ストア掲載そのものよりも、動作する成果物、設計判断、実装内容、検証過程を示すことで達成できる。

## 当面の優先順位

1. AndroidアプリとしてのMVP完成度を高める。
2. 実機QAを完了し、主要機能が動く状態を維持する。
3. READMEを、初見の人が目的・特徴・技術構成・起動方法を理解できる内容に整える。
4. Android実機での操作動画またはGIFを用意する。
5. スクリーンショット、設計判断、既知の制約、今後の改善案をポートフォリオ資料として整理する。
6. Web版の技術的実現性を確認し、費用と保守負担が小さい場合のみ、EAS HostingまたはVercel等でデモ公開を検討する。
7. Google Play一般公開は最後に再評価する。

## Google Play関連の扱い

- production AABの作成およびGoogle Play Consoleへの提出は、明示的な再決定があるまで進めない。
- development buildやAPKを使った実機検証は継続してよい。
- Google Play公開チェックリストは削除せず、将来再開できる資料として保持する。
- Play Consoleの登録、ストア掲載文、公開用画像、production rolloutは現時点の必須成果物に含めない。
- 「一度経験するためだけ」に一般公開することは、現在の目的に対して優先度が低い。

## 名前と識別子の扱い

### アプリ名

`FlexRoutine`は開発名として維持してよいが、日本人向けの正式な公開名としては分かりにくい可能性がある。正式名称は公開前に再検討する。

候補の方向性:

- 日本語で用途が伝わる短い名称
- 「寝坊や予定の崩れから立て直す」特徴が分かる名称
- ストア掲載名とホーム画面表示名を分ける構成

現時点では、Codexが独断でアプリ名を変更しないこと。

### Expo slug

Expoのslug `flexroutine` は技術上の識別子として当面維持してよい。一般ユーザー向け名称と一致させる必要はない。

### Android package name

現在の `com.flexroutine.mobile` は暫定値であり、一般公開用として確定したものではない。


- Google Play公開後のパッケージ名変更は別アプリ扱いになるため、公開前に最終決定する。

- ただし、既存ビルドやEAS設定への影響があるため、Codexは明示的な指示なしに変更しないこと。

## Expoアカウントの扱い

FlexRoutineは個人の学習・ポートフォリオプロジェクトであり、ExpoではPersonal用途として扱う。共同管理や法人所有が必要になった場合にのみOrganizationへの移行を検討する。

## Webデモについて

Web公開はGoogle Play公開の完全な代替ではなく、ポートフォリオ閲覧者が触れるデモ手段として検討する。

確認すべき点:

- SQLite、通知、音声、ハプティクス、共有機能などのWeb互換性
- ネイティブ版とWeb版で異なる機能の明示
- Web対応のためだけにアプリ構造を大きく複雑化しないこと
- 公開URLの維持費、更新負担、プライバシー上の扱い

Web対応コストが高い場合は、実機動画とスクリーンショットを優先する。

## Codexへの作業指示

この文書を読んだCodexは、以降の計画と実装で次を守ること。

1. Google Play一般公開を現在のゴールとして扱わない。
2. production AAB作成、Play Console提出、package name変更、正式名称変更を独断で進めない。
3. Android実機での完成度と検証可能性は維持する。
4. ポートフォリオ価値を高めるREADME、デモ資料、設計記録、QA資料を優先する。
5. Webデモは、既存のネイティブ実装を壊さず、追加コストが妥当な場合だけ提案する。
6. 公開方針に関わる変更を行う前に、この決定ログとの整合性を確認する。
7. Google Play公開を再提案する場合は、得られる経験・メリットと、本人情報・維持管理・更新義務のコストを併記する。

## 再検討する条件

次のいずれかが起きたとき、Google Play公開を再検討する。


- FlexRoutineを実際のユーザーへ継続提供したくなった。
- 収益化または利用者獲得を目指すプロジェクトへ移行した。
- Play公開経験そのものが、具体的な応募先や課題で必要になった。
- 公開後のメンテナンスを継続できる運用体制ができた。

再検討時には、無料公開、アプリ内課金、別アプリ化、Web提供、限定テストの各選択肢を比較して決める。
